Protocol Section
STUDY PURPOSE
The purpose of this study is to validate that MedAI’s usage of Github is in accordance with 21 CFR §820.70(i) Automated Processes and ISO 13485:2016 Medical devices — Quality management systems — Requirements for regulatory purposes.
OBJECTIVE AND SCOPE
The primary objective of this study is to validate the current usage of Github by MedAI against  21 CFR §820.70(i) Automated Processes.
MedAI does not use Github to maintain electronic records per the definition of “electronic record” in 21 CFR 820.11.  The source code maintained in GIthub is used to generate all software and firmware artifacts that comprise the MX1 Software System. As part of every software release, these generated artifacts are then delivered to the QMS per WI-005, Engineering Change Request, as the artifacts are considered “electronic records” per 21 CFR 802.11.
Github is a cloud-based code development platform and code repository. It uses Git, an open source version control system, to provide access control and traceability to support collaborative software development. MedAI uses Github as the code repository system for all product and custom non-product software used in the development of the P00 Imager Medical Imaging System and MX1 Portable X-ray Systems.
MedAI primarily uses Github to:
Maintain user access control to the MedAI codebase;
Maintain a complete record and version control* of the source code; and
Retain code change traceability
* Note that the overall MX1 Software System is identified by a 3-digit version number using the “major.minor.patch” convention in accordance with PLN-P01-025 - MX1 Software Configuration Management Plan, Rev. B. This versioning is recorded in the Software Bill of Materials that is created for every software release.
MedAI subscribes to the Github Teams plan. The MedAI organization is cloud-hosted on Github servers. Github is certified to the following:
SOC 1, Type 2
SOC 2, Type 2
Cloud Security Alliance CAIQ self-assessment (CSA CAIQ - Level 1)
ISO/IEC 27001:2013 certification
Cloud Security Alliance STAR certification (CSA STAR - Level 2)
GitHub.com Services Continuity and Incident Management Plan

DEFINITIONS
Repository - A repository, or repo, is a collection of files and folders that are version-controlled using Git
Local repository - A repository hosted on a local machine. Allows for individual contributions to a codebase without modifying the original repository
Remote repository - A repository hosted on an off-site and/or cloud-based server. Allows for multiple contributors to push code changes to a repository in a collaborative manner
Clone - Cloning is the process of creating a local copy of a repository (i.e. local repository) on a local machine
Commit - A snapshot of changes made to files in a repository. Every commit has a unique identifier (commit hash) and, optionally, a developer-typed commit message that briefly describes code change
Commit history - A record of all changes made to a file or set of files in a source version control system
Commit hash - A unique identifier that is generated for every commit made to a repository. It is generated by Git using the SHA-1 cryptographic hash function, which produces a 40-character string of hexadecimal characters. In Github, for ease of review, the first 7 or 8 characters may be shown instead of the complete 40-character hash.
Terminal - An input field in a text-based user interface screen for an Operating System (OS) or program. In this protocol, a terminal is used to run commands to transfer and retrieve files to a remote Github repository.
Electronic record - Any combination of text, graphics, data, audio, pictorial, or other information representation in digital form that is created, modified, maintained, archived, retrieved, or distributed by a computer system.
