Purpose
The purpose of this document is to establish a plan for usability activities to be performed during Design Control Phase 3 under DHF-008 for the MX1 Portable X-Ray System.
The usability plan shall guide MedAI on the documentation required to provide objective evidence of a complete Human Factors Usability Engineering Process for MX1 from its concept to commercialization.
The usability plan shall reflect the activities required throughout the product development lifecycle and shall guide the usability engineering process activities to be aligned with other development activities.
The plan shall outline the usability engineering project, the project timeline, and team member roles and responsibilities.
The original MX1 design underwent summative usability testing in VVPR-P01-081 under DHF-001. Per Project Plan PLN-P01-060, the MX1 system design is being iterated and developed under DHF-008. This document describes the usability testing plan for the current MX1 design, as there are changes to the software and hardware.

Definitions
Critical Task: A user task which, if performed incorrectly or not performed at all, would or could cause serious harm to the patient or user, where harm is defined to include compromised medical care.
Formative Evaluation: User interface evaluation conducted with the intent to explore user interface design strengths, weaknesses, and unanticipated use errors.
Summative Evaluation: User interface evaluation conducted at the end of the user interface development with the intent to obtain objective evidence that the user interface can be used safely.
User: Person interacting with (i.e. operating or handling) the medical device.
Use Error: User action or lack of user action while using the medical device that leads to a different result than that intended by the manufacturer or expected by the user.
Use Scenario: Specific sequence of tasks performed by a specific user in a specific use environment and any resulting response of the medical device.
User Interface: Means by which the user and the medical device interact.
User Interface Evaluation: Process by which the manufacturer explores or assesses the user interactions with the user interface.
Discussion
MX1 Portable X-Ray System User Interface
The MX1 hardware has been redesigned to include a handle on the cassette. The software system will include a new mode for fluoroscopic imaging; the fluoroscopy mode introduces changes to the software UI. The MX1 system, including the MX1 App, will be re-evaluated via formative and summative usability testing to ensure that the user interface can still be used safely.
Hardware UI
MX1 consists of an emitter and cassette.
The emitter and cassette are cordless and allow x-ray emission at various orientations as long as the x-ray beam is within the cassette active area.
The triggers are push buttons/triggers that provide tactile feedback to the operator.
The emitter UI provides the selection of exposure techniques that are selected using the push buttons below the screen.
The emitter UI includes a screen to aid the operator with positioning the emitter and the cassette.
The operator can manually collimate the x-ray beam through the use of pucks as well as through the manual collimation page in the software UI.
Software UI
The software UI allows the operator to configure the loading factors (kV, mAs).
The software UI includes a Viewfinder to assist the operator with aligning the emitter and cassette for imaging. Viewfinder is displayed on the emitter screen.
The operator can configure a worklist and enter patient data using the MX1 App.
The software UI allows the operator to select the desired mode (photograph, radiograph, DDR, fluoroscopy).
The interoperability of MX1 with its accessories shall be evaluated.
Any other user interfaces that are unique to the MX1 system shall be evaluated for use and user feedback.
Usability Engineering Project Timeline and Resources
Project Timeline
The user research was initiated in May 2021 during initial concept and feasibility evaluation for the MX1 project.
Initial Formative Evaluations with initial prototypes occurred in December 2021 and will continue through development.
A Summative Usability Evaluation was completed in April 2023 under DHF-001 on an initial design verification unit.
Formative usability evaluations focusing on the new MX1 software and UI design will occur in design Phase 3. A new summative usability evaluation will occur in design Phase 3 following the release of software version 3.2.0. Refer to the Project Plan PLN-P01-060 for project dates.
Team Roles and Responsibilities
Quality shall be responsible for:
Authoring the usability plan.
Generating the Usability Engineering File.
Human Factors Engineering shall be responsible for:
Authoring and executing formative and summative usability protocols and reports.
Performing risk analysis/identification of critical tasks and tasks related to safety.
Regulatory shall be responsible for reviewing and ensuring compliance with the usability standards.
Engineering shall be responsible for defining use specifications and user interface specifications.
Usability Engineering Process
The Usability Engineering Process shall help establish the process for implementing usability engineering in order to identify and minimize the overall use-related risks with the device.
The Usability Engineering Process shall start with initiation of user needs discovery.
MX1 user research consisted of interviews with various users and identification of markets that could potentially use the MX1 system.
The interviews were conducted virtually or in-person by the MedAI Human Factors Team.
The User Interviews, Use Scenarios, Market Features, and Market Summaries were recorded in document MEMO-P01-402 - User Needs Research.
Upon analyzing the user pain points, market requirements and the current process, user needs were drafted.
User needs will be integrated into the Design Inputs document (DR-P01-008) for the MX1 device. The DR will include user needs as well as resulting product requirements related to use, including those that address the user interface and ergonomics. A separate Use Specification document will be generated that contains information on target users and environments, and a separate User Interface Specification document will be generated that details all hardware and software user interface specifications.
A User-Related Risk Analysis (URRA) will be documented. The URRA will be used to establish critical tasks and tasks related to safety that will be tested during summative evaluation.
Input to the URRA may include any use errors documented in postmarket feedback for the P00 device as well as an FDA MAUDE database and TGA DAEN database search for similar devices.
Formative Usability Evaluation
Formative evaluation shall be conducted on the MX1 Portable X-Ray System to evaluate the design strengths, weaknesses, and anticipated use errors.
The formative evaluations shall occur prior to the summative usability testing and shall pertain to specific design or interface features under review/development. These formative evaluations may be recorded as MEMOs or VVPRs. The formative evaluations shall define the features subject to formative usability assessment and the extent to which the design elements are recognizable, understandable and operable by the user.
Formative evaluations shall inform device user interface design, focusing on the issues that the preliminary analyses indicated were most likely to involve use safety.
The formative evaluations shall:
Verify the implementation of the medical device user interface design against the requirements of the usability specifications.
Assess the effectiveness of measures implemented to reduce or eliminate use-related hazards or potential use errors.
The risk management team will evaluate use risks by reviewing points of interaction with the device for any instance of foreseeable misuse, as well as considering all steps, warnings and cautions in the device labeling.
Determine training requirements and inform the design of the labeling and training materials.
Inform the content and structure of the summative usability testing.
The methods used for formative evaluation should be chosen based on the need for additional understanding and clarification of user interactions with the device UI.
Formative evaluation may be conducted with varying degrees of formality and sample sizes, depending on how much information is needed to inform design.
Mock-up devices and preliminary prototypes may be used for the formative evaluation.
Preliminary analyses and evaluations, including formative evaluation, shall identify critical tasks.
Design modifications should be implemented and then evaluated for adequacy through Phase 2 of development until the device is ready for human factors validation testing (summative usability evaluation).
The formative evaluation protocol should specify the evaluation purpose, UI portion under assessment, use scenarios and tasks, evaluation participants, data collection and analysis methods, and how the results will be used.
Formative evaluation results should be used to determine whether design modifications are needed.
No formal acceptance criteria is established for formative evaluation. Instead, the risk analysis shall determine if further design iterations are required based on the effectiveness of risk controls and discovery of any new hazards.
When the formative evaluation(s) have demonstrated that the design elements are recognizable, understandable and operable by the user and use-related risks in the current design have been addressed and reduced to an acceptable level, the design may be frozen and a formal summative evaluation/human factors validation test may be performed.
Summative Usability Evaluation
Summative Evaluation/Design Validation shall be conducted by performing critical task analysis within simulated-use testing.
Summative Evaluation shall occur in Phase 3 of development. It shall validate the usability of the medical device according to the summative usability validation protocol.
In this simulated-use testing the test participant shall use the MX1 Portable X-Ray System in a realistic use scenario, but may not include all simulated conditions of use.
A protocol shall be developed to address the following for the final design validation/summative evaluation:
The test participant(s) shall represent the intended users of the device.
Task analysis shall include the participants performing all critical tasks related to the use and safety of MX1.
The device used for summative evaluation shall represent the final design (i.e. production-equivalent unit).
The methods used to collect data on the test participants’ performance (objective) and subjective assessment of all critical tasks.
The test protocol should also provide a rationale for the extent of device use and the number of times that participants will use the device.
Acceptance Criteria.
Risks associated with usability are considered to be acceptable if the usability acceptance criteria have been met. The acceptance criteria will be documented in the usability validation protocol for the device.
If the acceptance criteria documented in the usability validation plan are not met, then:
Further user interface design changes and accordingly-revised summative assessment shall be performed or,
If design changes to mitigate risks are not practical or would not reasonably result in risk mitigation, the medical benefits of the intended use shall be determined to outweigh the risk arising from use errors. If this evidence does not support the conclusion that the medical benefits outweigh the risk, then the risk is unacceptable.
Usability Engineering File
The Usability Engineering File shall list all the usability documents including the document number, description, purpose and reference section within the applicable standards.
It shall contain references to the following information:
User research/user interviews
Use Specification
User Interface Specifications
User Interface characteristics related to SAFETY and potential USE ERRORS
Known or foreseeable hazards and hazardous situations
Hazard related use scenarios
Formative and Summative Evaluation Protocols and Reports
