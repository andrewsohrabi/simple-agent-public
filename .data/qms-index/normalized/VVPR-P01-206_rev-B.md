STUDY PURPOSE
The purpose of this study is to demonstrate that MX1 MedAI Diagnostic Tool (ODT) v3.1.0-alpha meets the requirements as stated in MEMO-P01-604 - MedAI Diagnostic Tool Software Requirements Specification Rev. H for WorkStations WS-001, WS-002, WS-004, WS-005 and WS-006.
OBJECTIVE AND SCOPE
Verify the software requirements established by MedAI for ODT v3.1.0-alpha release installed on the following WorkStations:
WS-001 - ES-10003 Emitter Verification
WS-002 - MS-10008 Collimator Verification
WS-004 - MS-10149 Camera Sensor Board Verification
WS-005 - MS-10301 HMI Display Verification
WS-006 - MS-10141 PMUX and MS-10568 Wireless Transmitter PCBA Verification
Verify the software meets the requirements in ODT Software Requirements Specification, MEMO-P01-604 Rev H.
Verify ODT v3.1.0-alpha accurately assesses input data using a test firmware version (ODT Tripper v1.1.1) created and installed on Units Under Test (UUT) to send ODT two types of information:
Nominal, low and high parameter values to demonstrate ODT accurately assesses input data as PASS or FAIL.
True and False data to demonstrate ODT can differentiate between true and false input data

Hardware Mock Testing
Hardware mock testing is a software testing technique where the behavior of real hardware components is simulated using software-based “mock objects” allowing developers to test their code that interacts with hardware without needing the actual physical hardware present. To verify ODT capabilities for detecting hardware failures, ODT Tripper simulates inputs to ODT that represent faulty hardware inputs without requiring faulty hardware to be present. During verification, ODT Tripper firmware provides ODT values outside of ODT’s acceptable value ranges. Depending on if ODT sets the power supply to LOW, NOM, or HIGH voltage, the voltage threshold at which ODT considers a failure changes.
ODT Tripper firmware has register D3 which allows the operator to mock battery input ranges that the ODT Tripper Firmware must return to match the active ODT Thresholds. The payload values for mocking the power supply are 00=Low, 01=Nominal and 02=High.
ODT Tripper firmware has register D4 which allows the operator to mock readback values to be below, within or above the threshold (Low, Nominal and High). The payload values for mocking readback values are 00=Low, 01=High and 02=Nominal.

Report Section
Protocol Deviations
The ODT7.1 requirement was removed in MEMO-P01-604 Rev H, but was inadvertently kept in the protocol. Refer to ECR-639. This requirement is no longer applicable and as such was removed and not tested.
The verification of Emitter Main WorkStation WS-001 ODT requirements required an MS-10401, HMI Assembly, and display FFC which were not previously listed in the setup.
ODT4.14 verification included a command for ODT tripper that included the wrong byte (00 instead of 01). Command 01 was used.
The verification of Collimator WorkStation WS-002 ODT requirements required WS-002, a Collimator, MS-10200, and a faulty Collimator which was not previously listed in the setup.
ODT8.17 verification of failures referred to PMUX Charge Current Setting Test, but should have referred to PMUX System Current Setting Test with the appropriate set points. Therefore, two verification steps were added which addressed verifying read back values when System current equalled 4000mA and 5000mA and does not meet low requirements (in Pass Criteria). Testing confirmed these two cases failed ODT as intended.
The verification of Power Cleat and Wireless Charger Verification WorkStation for the Wireless Charger, (MS-10568), WS-006 ODT 10.X requirements required WS-006 which was not previously listed in the setup. The workstation component was used as the UUT to verify ODT.
Power Cleat and Wireless Charger Verification WS-006 ODT verification listed MS-10141, which is redundant, as WS-006 includes one already. The workstation component was used as the UUT to verify ODT.
Clerical errors were addressed as encountered.
